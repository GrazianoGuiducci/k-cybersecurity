# K-Cybersecurity

**A kernel for developing system awareness and security capabilities through real work.**

K-Cybersecurity connects technical, physical, cognitive and semantic security.
It gives an operating LLM or agent a semantic core, practical competence
knowledge and a way to learn from consequences while its environment changes.

The [founding manifesto](MANIFESTO.md) preserves Graziano Guiducci's original
Italian vision: a system should recognize what is happening, respond beyond
its existing defensive capabilities and potentially counterattack. The horizon
also includes stopping an attacker and helping bring them to justice. This
vision guides the development of new capabilities and means.

## Start in your own environment

Make this folder readable to your assistant and ask:

> Start K-Cybersecurity from BOOT.md. Understand our system and what I want to
> protect. Use the available competences and means, develop the knowledge we
> need, and preserve what makes future work more capable. Our system is
> [context], my intent is [direction], and the action mandate is [scope].

The receiver builds its situated incarnation: context, access, capabilities,
working knowledge and continuity belong to that instance. The public core
carries reusable knowledge and can learn from suitable contributions.

## Security during everyday work

The kernel's current method helps an agent distinguish **information, embedded instructions, and actual authority**, trace how content changes across tools and agents, and recognize when a functional change affects existing safeguards. The same faculty can examine whether the kernel's own security knowledge is reaching the work that needs it.

[Security during work (Italian guide)](docs/SECURITY_IN_OPERATION.md) · [Illustrative migration scenario (Italian)](examples/security-through-changes.md) · [Changes](CHANGELOG.md)

## Source, delegation and host execution

A document may remain unchanged while permission to act is revoked; the source may instead change during a delegated operation. K-Cybersecurity makes **the source accepted at the effect**, **current authorization** and **the actual host result** distinguishable. An intact audit log, an agent's proposal and the host's protection have different evidence.

The same method reaches cases where **configuration starts tools before model interpretation** or a suspended action **resumes after an approval**.

## Resolved target and recipient

The kernel also follows the object actually reached by a tool and the intended
recipient of results. An authorized path can resolve to another resource; an
authentic response can belong to a different session. The integration competence
keeps the mandate connected to the target and delivery, while preserving
legitimate links and cooperation.
